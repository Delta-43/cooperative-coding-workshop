4 · Decisions

  • Base (kept): Guided Coding type and structure: Anton titles (first word filled, second outlined), JetBrains Mono for data and the meta rows, Switzer for reading text, corner brackets on the projector screens.
  • New in draft 2, the comic print language: taken from a style reference as a way of building things, not as a look. Its colours and fonts are not used.
  • Colour (final): five colours and navy tints, nothing else. Navy #011627 is the field and the ink. White #FDFFFC is text and paper. Teal #2EC4B6 is the pond: actions, data, progress, focus. Orange #FF9F1C is the winner, one panel per screen. Red #C8102E is stickers and errors; on navy it is only for large shapes, and small error text uses a lighter red tint.
  • Shape: comic panels. Every block, button, tag, input and sticker has square 90 degree corners. Only the phone bezel stays round, because it is the device.
  • Panels: a 3 px ink edge, a halftone dot fill and a hard offset shadow with no blur. Ink would vanish on the navy field, so shadows are teal (main actions, inputs, QR, the bar) or white (winner panel, second button, sticker).
  • Buttons: two kinds only. Main: white paper with dots, navy capitals, the arrow in a navy square, teal shadow. Second: teal paint with dots, white shadow. Hover lifts the panel 2 px, and pressing pushes it into its shadow.
  • Winner: the one orange halftone panel on a screen, with the orange crown. Other rows stay plain navy blocks so the winner pops.
  • Print details: faint halftone dots on the screen field. Progress is square printed blocks (solid, hatched, outline). The centre meta item is a stamped mono tag.
  • Comic touches, kept rare: one tilted sticker at most per screen (lobby and final only). The duck speaks in a speech bubble on the waiting screen and stands on the final scoreboard.
  • Projector floor (draft 4): nothing a player or host needs to read is under 16 px on a 960 by 540 frame. Outlines that carry meaning use a lighter rule colour, so they survive a washed-out projector. The meta rows carry real data only: room, step and count.
  • Class size: built for 30 (the contract's room limit). The lobby shows a count and a name list. The question screen shows only a count and a bar: no names on the projector. Players who have not answered see the count on their phone. The answer screen names the top 3, the final screen the top 5, and everyone else is pointed to their phone.
  • Answer screen, staged: first the question, an outlined "?" and the empty bar with every guess as a square beside it. Space fills the bar: uneven eased bursts, a small shake, a slight overshoot, then it settles on the answer in about 2.2 seconds. Only then do the number, the answer line and the top 3 appear. The scale runs from the lowest to the highest guess (plus a margin), so the stop height changes every question. Guesses far outside are counted at the ends ("2 guesses above"). Reduced motion skips straight to the end.
  • Plain scoring words: "off by 3", not "3.4% off". Inside one question, ranking by relative error and by plain distance give the same order, so the simpler words are exact.
  • Ties (contract change): no shared places. Equal distance: the earlier answer ranks higher. Equal final totals: the lower total answer time ranks higher. "Change answer" resets that player's time, so nobody can lock in an early time and then edit. The backend scoring and the contract need this change.
  • Host controls: the same three keys on every screen. Space does the main action (start, reveal, fill, next). Backspace steps back one screen, so a reveal can be undone. Esc opens the player menu, where a host removes a player and confirms. On the final screen Space must be pressed twice for a new game, so a stray click cannot wipe the scores.
  • Phone endings: every player gets a screen made for them: closest, beaten on time, no points, no answer (or too late), winner or mid-table. The tie rule is said up front: in the lobby, on the waiting screen, and on the sent screen (changing an answer restarts your time). Errors name the problem and the fix (wrong code, lost connection).
  • Type: poster leading (0.85) and slightly larger titles. Question text stays Switzer so a long question stays readable.
  • Icons: Phosphor only.
  • Motion: one moment per screen. The reveal bar is the big one. The top 3 land one after another when it settles. Everything else is a 150 to 250 ms state change.
  • Open: the web address on H1 is a guess and too long to type from the back row. Make a bit.ly link once the site is deployed.

The AI toolkit

Five words you hear every week. Three questions sort all of them.

Three questions

Q1

What enters the context?

Instructions, files, tool results. Everything the model reads costs space and can carry instructions.

Q2

Who decides it runs?

You type it, the agent picks it, or a script calls it.

Q3

Where does it run?

On your machine, in the vendor's cloud, or on someone else's server.

Skill vs MCP

Skill

Changes what the agent knows how to do

"Critique this design." "Write it in my voice."

MCP

Changes what the agent can reach

"List my Workers." "Read this ticket."

"MCP provides the connection; a skill teaches Claude how to use it well."

Anthropic, Extend Claude Code

Subagents: start with one

Reads split well

Research, review, search. Each worker reads in clean context and returns a summary. Our design review ran two reviewers that never saw each other's work.

Writes do not

Two writers on the same files collide, for agents and for people. Split writes only by file, folder or branch. That is why we split backend and frontend.

"Never edit .env"

An instruction is a request, not a guarantee. Hooks, permissions and the server's rules are the guarantee.

Request

AGENTS.md, CLAUDE.md, a skill, a prompt

Local guard

Permission prompts, a hook that blocks a command

Server guard

Branch protection: nothing reaches main without a PR and a human

The GitHub flow

Phases, issues, branches, pull requests, CI and sign-off.

From plan to main

PhaseA milestone with one sign-off issue
IssueOne task, "done when" and a verify command
BranchOne per issue, one agent
PRSmall, with the verify output
CIBuild, tests, contract examples
ReviewThe other human approves

A small-change lane skips the phase sign-off: a typo or copy fix needs only an issue and a PR.

Anatomy of an issue

Backend: break equal-error ties by answer time

Done whenEqual error ranks the earlier answer first. A changed answer restarts the time.
Verifycd backend && npm test
Do not touchfrontend/

The same command runs for the agent, for the human and for CI.

Every pull request

  • CI must pass. The branch rule blocks the merge button until it does.
  • The other person reviews. One approval. Agents can comment, but a human approves.
  • Explain it with the agent closed. What does it change, and what breaks if it is wrong?
  • Keep it small. A size you can read in five minutes.
  • One fresh-context review. A read-only subagent checks the diff against the issue.

Five habits

  • Give the agent the least you can. One repo, a short-lived token, no real secrets in the folder.
  • Everything it reads is untrusted. Issues, web pages, skills and MCP servers can all carry instructions.
  • Keep the permission prompts on. No "skip permissions" outside a throwaway machine.
  • Nothing reaches main without a PR and a human.
  • You own what you ship. Explain it, say AI helped, keep personal data out.
